# MIG-01: Capture source inventory and freeze migration contracts

## Prerequisites
None; start immediately.

## Ownership boundary
`docs/contracts/, fixtures/, migration/inventory/`. Work on a dedicated `codex/mig-01` branch/worktree. Do not edit another task's owned files without coordinating. Integrate schema changes through MIG-01 and renderer command changes through MIG-04.

## Work
Obtain a private WXR export, full uploads archive, theme/custom CSS/settings and plugin inventory. Reconcile published posts/pages with crawl, REST API, feeds and available sitemap; wp-sitemap.xml returned 404 during initial inspection. Record counts, source IDs, URLs, timestamps, taxonomies, media and backend features. Inventory original masters, observed legacy media URLs (including size-suffixed variants/CDN aliases), and references from crawl/rendered snapshots; absence from a crawl does not establish a URL variant is unused. Measure source-repository and built-output projections separately against GitHub Pages' recommended <1 GB source repository size and hard 1 GB published output cap, and propose headroom budgets. Publish sanitized fixture examples and versioned content, asset and route schemas, including fields for legacy URL compatibility decisions and responsive rendition requirements.

## Inputs and outputs
Consume the versioned contracts and sanitized fixtures from MIG-01 (MIG-01 creates these). Produce implementation, tests and an evidence report within the ownership boundary. Use fixtures to work independently of production data; never invent production content.

## Acceptance criteria
- [ ] Every published item is accounted for; inventory distinguishes masters, observed legacy media URLs/references and generated rendition requirements; no crawl absence is treated as proof that unobserved variants are unused; source-repository and published-output sizes are measured/projected separately; no private export data is committed; schema fixtures cover HTML, shortcode, gallery, code, video and Unicode cases.
- [ ] Document inputs, outputs, errors and reproducible verification in the PR.
- [ ] Include evidence against every acceptance criterion and identify remaining blockers.

## Verification contract
Implement and run `python -m unittest discover -s tests/contracts -v` as part of this task. These future commands are acceptance contracts, not commands available in the initial planning scaffold. MIG-07 wires the completed suites into CI; coordinate shared package scripts with MIG-04.

## Handoff
Link the PR and evidence here. Consumers use the committed contracts/artifacts, not another agent's uncommitted working tree. Do not change production DNS as part of any task other than approved MIG-09.
