# MIG-07: Extend CI/CD with full migration fidelity gates

## Prerequisites
01 contracts; CI scaffold already exists. Coordinate generator commands with 04.

## Ownership boundary
`.github/, tests/fidelity/, scripts/verify/, requirements-dev.txt`. Work on a dedicated `codex/mig-07` branch/worktree. Do not edit another task's owned files without coordinating. Integrate schema changes through MIG-01 and renderer command changes through MIG-04.

## Work
Extend existing master push/PR workflow with generator lint, importer unit tests, build, local links/assets and legacy-media mapping checks, Playwright interactions and source/target screenshot comparisons. Verify responsive image markup, rendition coverage, alt/caption preservation, intrinsic dimensions, LCP loading priority, lazy loading below fold, canonical/social metadata and image sitemap. Check that the generated width set is deliberately bounded from measured blog-column/gallery/hero breakpoints and source dimensions once layout inventory exists; report variant counts/bytes, and account for every generated candidate in output-size checks even though browsers generally download only one suitable `srcset` candidate per view. Enforce a project-defined built-output budget with headroom below Pages' hard 1 GB published-output cap, while separately reporting source-repository size against the recommended <1 GB guideline; never confuse these limits. Add repeatable image/page-weight and loading checks with realistic budgets derived from inventory and a recorded baseline, not an unsupported numeric Lighthouse score promise. Preserve check-before-deploy dependency and least privilege. Build production-root and preview-subpath variants; deploy only the preview until cutover. Upload comparison reports. Bound/flaky external checks separately from deterministic checks.

## Inputs and outputs
Consume the versioned contracts and sanitized fixtures from MIG-01 (MIG-01 creates these). Produce implementation, tests and an evidence report within the ownership boundary. Use fixtures to work independently of production data; never invent production content.

## Acceptance criteria
- [ ] A deliberately missing asset or legacy-media mapping, altered article, broken fragment, invalid SEO/image metadata, exceeded output/performance budget or screenshot regression fails CI. PRs cannot deploy. Only validated master artifacts deploy to Pages. Test harness consumes frozen fixtures and is runnable locally; it separately reports source repository and published output sizes.
- [ ] Document inputs, outputs, errors and reproducible verification in the PR.
- [ ] Include evidence against every acceptance criterion and identify remaining blockers.

## Verification contract
Implement and run `npm run test:fidelity && python -m unittest discover -s tests -v` as part of this task. These future commands are acceptance contracts, not commands available in the initial planning scaffold. MIG-07 wires the completed suites into CI; coordinate shared package scripts with MIG-04.

## Handoff
Link the PR and evidence here. Consumers use the committed contracts/artifacts, not another agent's uncommitted working tree. Do not change production DNS as part of any task other than approved MIG-09.
