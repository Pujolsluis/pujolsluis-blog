# MIG-06: Define Git-based editorial operation and feature replacements

## Prerequisites
01 contract and feature inventory; parallel with 02–05.

## Ownership boundary
`docs/editorial/, scripts/editorial/, tests/editorial/`. Work on a dedicated `codex/mig-06` branch/worktree. Do not edit another task's owned files without coordinating. Integrate schema changes through MIG-01 and renderer command changes through MIG-04.

## Work
Document and implement Git-based Hugo authoring: create and edit all posts as Markdown with Hugo front matter, add media at exact public paths, preview locally/through a PR, and publish through reviewed GitHub Actions builds. Validate metadata, drafts, media, tags and publication dates; document Hugo commands and examples. Support future publishing through scheduled builds if needed. Inventory forms, subscriptions, commerce and other backend features; present replacement choices for owner decision. Comments are explicitly out of scope: do not migrate comment records to the blog or add comment functionality. No other observed capability may be silently omitted; dispositions remain open until the owner decides.

## Inputs and outputs
Consume the versioned contracts and sanitized fixtures from MIG-01 (MIG-01 creates these). Produce implementation, tests and an evidence report within the ownership boundary. Use fixtures to work independently of production data; never invent production content.

## Acceptance criteria
- [ ] Owner can create, edit and publish a fixture post without WordPress; drafts/future posts stay out of deployed output and feeds; scheduled publication is tested if enabled; each discovered backend feature including commerce has an owner-approved disposition; no silent omissions.
- [ ] Document inputs, outputs, errors and reproducible verification in the PR.
- [ ] Include evidence against every acceptance criterion and identify remaining blockers.

## Verification contract
Implement and run `npm run test:editorial` as part of this task. These future commands are acceptance contracts, not commands available in the initial planning scaffold. MIG-07 wires the completed suites into CI; coordinate shared package scripts with MIG-04.

## Handoff
Link the PR and evidence here. Consumers use the committed contracts/artifacts, not another agent's uncommitted working tree. Do not change production DNS as part of any task other than approved MIG-09.
