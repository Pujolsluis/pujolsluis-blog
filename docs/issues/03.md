# MIG-03: Archive original media and implement asset mapping

## Prerequisites
01 asset contract; fixture development can run alongside 02.

## Ownership boundary
`scripts/import_media/, static/wp-content/, tests/import_media/, migration/assets/, .gitattributes`. Work on a dedicated `codex/mig-03` branch/worktree. Do not edit another task's owned files without coordinating. Integrate schema changes through MIG-01 and renderer command changes through MIG-04.

## Work
Preserve owned originals byte-for-byte under Hugo's `static/wp-content/` tree so legacy `/wp-content/...` paths remain intact. Track every binary file in Git LFS, enforce that policy in `.gitattributes`, and keep backups/private exports outside the public repository. GitHub documents that Pages does not serve LFS directly; test an Actions workflow that fetches/materializes LFS files and deploys a static artifact, and do not assume compatibility until a binary fixture passes CI and Pages staging. The published output must contain real binary bytes rather than LFS pointer files. If that workflow fails, document the result and request an owner decision on external owned asset hosting or another platform before changing the architecture. Record source URL, exact public destination path, MIME, bytes, SHA-256, dimensions and every reference. Exact URL compatibility comes from source records, rendered HTML and explicit manifests; absence from a crawl is not evidence that a URL is unused. Derive a bounded set of responsive renditions from measured layout breakpoints and actual display needs; count every deployed rendition in the Pages output budget. Treat processed renditions as derivatives: Hugo image processing does not preserve source metadata, so keep exact originals as archival/direct-download sources and verify rendition appearance and dimensions. Do not replace originals or claim metadata fidelity for derivatives without tests. Measure Git source repository size separately from LFS storage/bandwidth and the hard 1 GB published-output cap. Cover srcset, CSS backgrounds, posters, captions, audio, video and downloads. Preserve embed provider IDs, parameters, aspect ratios and captions. Detect old-host/CDN dependencies. Do not transcode or silently drop assets to fit limits.

## Inputs and outputs
Consume the versioned contracts and sanitized fixtures from MIG-01 (MIG-01 creates these). Produce implementation, tests and an evidence report within the ownership boundary. Use fixtures to work independently of production data; never invent production content.

## Acceptance criteria
- [ ] All owned originals and generated renditions have verified hashes and explicit path mappings; every binary file is LFS-tracked; an end-to-end Pages staging test proves whether Actions can fetch real LFS contents and publish no pointers; no unresolved references; embedded players pass playback checks. Every legacy public media URL has a compatibility disposition. Budget uses measured archive, LFS usage and built-output sizes. If LFS/Pages limits require external owned storage, document a decision and get owner agreement before architecture changes.
- [ ] Document inputs, outputs, errors and reproducible verification in the PR.
- [ ] Include evidence against every acceptance criterion and identify remaining blockers.
