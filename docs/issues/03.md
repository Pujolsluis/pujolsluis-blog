# MIG-03: Archive original media and implement asset mapping

## Prerequisites
01 asset contract; fixture development can run alongside 02.

## Ownership boundary
`scripts/import_media/, static/wp-content/, tests/import_media/, migration/assets/, docs/media-optimization.md`. Work on a dedicated `codex/mig-03` branch/worktree. Do not edit another task's owned files without coordinating. Integrate schema changes through MIG-01 and renderer command changes through MIG-04.

## Work
Build an evidence-based image-use manifest from published WXR content, frozen rendered pages, CSS/theme references, social/featured metadata and live galleries. Include only images required to render the live published site and owner-approved legacy media URLs; exclude orphan uploads, backup/theme package files, duplicate files, unused WordPress-generated dimensions and cache/thumbnails. Keep full-resolution source masters and backups outside the public repository. Optimize each selected image before committing it as an ordinary Git file under Hugo's `static/wp-content/` tree, retaining the public URL/path where required. Preserve the displayed crop, orientation, aspect ratio, transparency, caption and alt text. Resize to the maximum measured display size plus required device-pixel density. Compare suitable encodings and quality settings on representative images; choose the smallest output with no visible degradation at its real page size. Use lossless treatment for assets that require exact pixels (such as logos/diagrams); remove nonessential metadata such as GPS data while retaining required copyright/licensing information, and keep accessibility text in page markup. Ship duplicate fallback formats only when browser testing requires them. Record source path, output path, source/output hashes, dimensions, format, byte size, references and visual-review result. Do not commit unused originals or every WordPress size variant. Set per-role byte budgets (aim for 1 MB or less where visual quality allows and keep every Git object below GitHub's 100 MB enforced limit). Generate responsive variants only for actual layout breakpoints and include each one in output/repository budgets. Preserve selected legacy media paths; classify every excluded old path with a reason and explicit compatibility disposition. Keep videos/provider embeds and non-image media in the asset inventory, but do not download third-party video or introduce a large binary without source evidence and an owner-approved size/hosting decision. Document the reproducible optimization settings and quality review in `docs/media-optimization.md`.

## Inputs and outputs
Consume the versioned contracts and sanitized fixtures from MIG-01 (MIG-01 creates these). Produce implementation, tests and an evidence report within the ownership boundary. Use fixtures to work independently of production data; never invent production content.

## Acceptance criteria
- [ ] Every image referenced by published content/theme/live metadata is present at its required path; each excluded upload/variant has a recorded reason; optimized outputs have source/output hashes, correct dimensions and no visible degradation at actual rendered sizes. Only needed images and measured responsive variants are committed as ordinary Git blobs. Media references resolve case-sensitively, and selected legacy paths have explicit compatibility dispositions. Every image stays within its role-based byte target and GitHub's enforced per-file limit; repository growth and built output meet measured budgets with headroom. Embedded videos/players retain provider IDs/settings and pass playback checks.
- [ ] Document inputs, outputs, errors and reproducible verification in the PR.
- [ ] Include evidence against every acceptance criterion and identify remaining blockers.
