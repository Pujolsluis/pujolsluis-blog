# MIG-02: Implement deterministic WordPress content import

## Prerequisites
01 contracts; develop using sanitized fixtures before real export is available.

## Ownership boundary
`scripts/import_content/, content/, tests/import_content/`. Work on a dedicated `codex/mig-02` branch/worktree. Do not edit another task's owned files without coordinating. Integrate schema changes through MIG-01 and renderer command changes through MIG-04.

## Work
Parse WordPress WXR and available frozen rendered snapshots into structured metadata plus a Hugo content/front-matter adapter. Every blog post must be a `.md` file: convert article text and common structures to Markdown, map fidelity-verified media to Hugo shortcodes, and retain complex source blocks as validated raw HTML inside the Markdown body. Pages, portfolio entries and attachment routes may remain HTML where conversion could alter their semantics. Preserve source IDs, original paths, dates/time zones, authors, taxonomy, excerpts, anchors and RSS GUIDs. Reject unknown blocks/shortcodes with per-record evidence. Separate private drafts from published artifacts. Make repeat imports idempotent and support a final delta import.

## Inputs and outputs
Consume the versioned contracts and sanitized fixtures from MIG-01 (MIG-01 creates these). Produce implementation, tests and an evidence report within the ownership boundary. Use fixtures to work independently of production data; never invent production content.

## Acceptance criteria
- [ ] Fixture import is repeatable; all source records reconcile; normalized visible text, ordering and code whitespace match; unsupported content fails visibly with a per-record evidence trail; Hugo builds the produced content.
- [ ] Document inputs, outputs, errors and reproducible verification in the PR.
- [ ] Include evidence against every acceptance criterion and identify remaining blockers.

## Verification contract
Implement and run `python -m unittest discover -s tests/import_content -v` as part of this task. These future commands are acceptance contracts, not commands available in the initial planning scaffold. MIG-07 wires the completed suites into CI; coordinate shared package scripts with MIG-04.

## Handoff
Link the PR and evidence here. Consumers use the committed contracts/artifacts, not another agent's uncommitted working tree. Do not change production DNS as part of any task other than approved MIG-09.
