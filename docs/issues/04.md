# MIG-04: Build static blog renderer matching the existing theme

## Prerequisites
01 contracts; use fixture content, independent of 02/03 completion.

## Ownership boundary
`site/, public/theme/, tests/rendering/`. Work on a dedicated `codex/mig-04` branch/worktree. Do not edit another task's owned files without coordinating. Integrate schema changes through MIG-01 and renderer command changes through MIG-04.

## Work
Select and lock the static generator after inventory; proposed default is Astro static output with preserved article HTML. Reproduce the observed TheBlogger theme, fonts, responsive layouts, galleries, widgets and interactions using legitimately available assets. Implement image rendering with Astro-processed assets for generated responsive variants. Select a deliberately bounded width set only after measuring blog-column, gallery and hero breakpoints against source dimensions; avoid hard-coded widths until the rendered-layout inventory provides evidence. Report generated variant counts and bytes, and check them in CI. Browsers generally download one suitable `srcset` candidate per image view, while every generated candidate still contributes to published output size. Preserve fallback `src`, `srcset`, layout-appropriate `sizes`, explicit intrinsic dimensions/aspect ratio, source alt text/captions/available metadata, and original links where required. Prioritize likely LCP/hero images and lazy-load below-fold media. Use standard `img`/`picture` markup. Do not assume every WordPress size variant is needed or unused merely because a crawl did not find it; follow MIG-01/03's inventory and legacy URL compatibility policy. Document licenses. Keep generator dependencies and lockfile owned by this task.

## Inputs and outputs
Consume the versioned contracts and sanitized fixtures from MIG-01 (MIG-01 creates these). Produce implementation, tests and an evidence report within the ownership boundary. Use fixtures to work independently of production data; never invent production content.

## Acceptance criteria
- [ ] Fixture pages match source screenshots at mobile/tablet/desktop sizes; no unexplained visual differences; theme works at repository subpath and domain root; keyboard navigation works. Image markup has fallback src, appropriate srcset/sizes and dimensions; alt/caption fidelity is checked; likely LCP images are not lazy-loaded and below-fold media is lazy-loaded. Image loading and page weight meet inventory-grounded budgets.
- [ ] Document inputs, outputs, errors and reproducible verification in the PR.
- [ ] Include evidence against every acceptance criterion and identify remaining blockers.

## Verification contract
Implement and run `npm run test:rendering && npm run build` as part of this task. These future commands are acceptance contracts, not commands available in the initial planning scaffold. MIG-07 wires the completed suites into CI; coordinate shared package scripts with MIG-04.

## Handoff
Link the PR and evidence here. Consumers use the committed contracts/artifacts, not another agent's uncommitted working tree. Do not change production DNS as part of any task other than approved MIG-09.
