# MIG-04: Build static blog renderer matching the existing theme

## Prerequisites
01 contracts; use fixture content, independent of 02/03 completion.

## Ownership boundary
`hugo.toml, layouts/, assets/, static/theme/, tests/rendering/`. MIG-02 owns imported `content/`; coordinate the importer/render boundary through MIG-01 contracts. Work on a dedicated `codex/mig-04` branch/worktree. Do not edit another task's owned files without coordinating. Integrate schema changes through MIG-01 and renderer command changes through MIG-04.

## Work
Implement Hugo as the selected static generator for GitHub Pages. Consume the importer’s Hugo content/front-matter adapter and render preserved, validated WordPress HTML where Markdown conversion loses fidelity. Reproduce the observed TheBlogger theme, fonts, responsive layouts, galleries, widgets and interactions using legitimately available assets. Add Hugo shortcodes only for embeds/galleries when they preserve validated source behavior. Document licenses. Keep Hugo configuration, dependencies, layouts and build commands owned by this task.

## Inputs and outputs
Consume the versioned contracts and sanitized fixtures from MIG-01 (MIG-01 creates these). Produce implementation, tests and an evidence report within the ownership boundary. Use fixtures to work independently of production data; never invent production content.

## Acceptance criteria
- [ ] Fixture pages match source screenshots at mobile/tablet/desktop sizes; no unexplained visual differences; theme works at repository subpath and domain root; keyboard navigation works; imported Hugo content builds successfully.
- [ ] Document inputs, outputs, errors and reproducible verification in the PR.
- [ ] Include evidence against every acceptance criterion and identify remaining blockers.

## Verification contract
Implement and run `hugo --minify` and the rendering checks implemented by this task as part of this task. These future commands are acceptance contracts, not commands available in the initial planning scaffold. MIG-07 wires the completed suites into CI; coordinate shared package scripts with MIG-04.

## Handoff
Link the PR and evidence here. Consumers use the committed contracts/artifacts, not another agent's uncommitted working tree. Do not change production DNS as part of any task other than approved MIG-09.
