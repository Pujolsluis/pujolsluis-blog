# MIG-05: Preserve routes, metadata, feeds and blog discovery

## Prerequisites
01 route contract; parallel fixture work with 02–04.

## Ownership boundary
`site-routing/, tests/routes/`. Work on a dedicated `codex/mig-05` branch/worktree. Do not edit another task's owned files without coordinating. Integrate schema changes through MIG-01 and renderer command changes through MIG-04.

## Work
Generate original permalinks, taxonomy/author archives, pagination, feeds, attachments, fragments, canonical metadata, social metadata and custom 404. Implement static search if required by inventory. Inventory query URL aliases such as ?p=ID and search queries; document Pages inability to implement arbitrary HTTP redirects/status behavior. Choose compatibility mechanism and require acceptance for any deviation.

## Inputs and outputs
Consume the versioned contracts and sanitized fixtures from MIG-01 (MIG-01 creates these). Produce implementation, tests and an evidence report within the ownership boundary. Use fixtures to work independently of production data; never invent production content.

## Acceptance criteria
- [ ] Every inventoried route and fragment resolves; internal links pass in both base-path modes; outbound links remain identical with pre-existing failures reported separately; RSS GUIDs remain stable; staging is noindex and omitted from discovery.
- [ ] Document inputs, outputs, errors and reproducible verification in the PR.
- [ ] Include evidence against every acceptance criterion and identify remaining blockers.

## Verification contract
Implement and run `npm run test:routes` as part of this task. These future commands are acceptance contracts, not commands available in the initial planning scaffold. MIG-07 wires the completed suites into CI; coordinate shared package scripts with MIG-04.

## Handoff
Link the PR and evidence here. Consumers use the committed contracts/artifacts, not another agent's uncommitted working tree. Do not change production DNS as part of any task other than approved MIG-09.
